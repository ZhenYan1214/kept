## 0. 一句話

**一筆災難善款，會經過基金會、衛福部、縣府、公所好幾手才到災民手上，但每經過一手，大眾能看到的資訊就少一層，災民對這筆錢怎麼用也沒有任何一票。Kept 讓每一手的承諾與交付都可驗證，並讓通過認證的災民對善款用途有匿名的一票。**

## 3. 仍然存在的缺口（逐條附證據）

### G1：從撥款到送達的鏈，每經過一手就斷一截
- 賑災基金會截至 2026-09-25：**已支出（含預撥）12.09 億元，已核銷 4,915 萬元（約 4%）**。其中至少約 11.1 億元預撥給衛福部。基金會說明，預撥是因為賑災緊急，之後再依各單位名冊查核、多退少補。基金會本身**不持有發放明細**，由衛福部或縣府造冊發放 — [tf4dr.org](https://www.tf4dr.org/fundraising_plans/156/credits)
- 縣府 0923 專戶：收入 3.11 億元，公告形式是 JPG 圖片；支出明細 PDF **停在 2025-12-26**，只列 5 個計畫；委員會報表把「匡列數」當成「支出」；最新進度只出現在會議紀錄 PDF — [花蓮縣政府](https://www.hl.gov.tw/ysh/News.aspx?n=41293&sms=29016)；[會議資料](https://sa.hl.gov.tw/Upload/202606160928010835531.pdf)
- **結論：** 大眾只看得到第一手（捐款 → 基金會 → 預撥）。之後「實際發給多少戶、多少錢、有沒有送到」，沒有任何一方公開到可以驗證的程度。
> 措辭規範：4% 的核銷率**不代表有弊**，預撥後再核銷是正常的緊急作業程序。我們要指出的是「已撥出」和「已送達、已驗證」之間的落差，大眾看不見。

### G2：災民在善款決策中沒有一票
- 賑災基金會章程：董事全部由行政院選聘，**沒有受災者名額** — [章程](https://www.tf4dr.org/constitution)
- 花蓮縣作業要點第 3 點：受災民眾最多推派 5 人**列席**，經主席同意才能發言，**沒有表決權**；第三屆委員名單（2026-03 起）**沒有受災戶代表** — [作業要點](https://glrs.hl.gov.tw/glrsout/LawContent.aspx?id=GL001170)；[名單](https://sa.hl.gov.tw/Upload/202609230857200732221.pdf)
- 太魯閣號事故（2021）一開始只給受害者 2 席，被批評為「歷來最低」 — [今周刊](https://www.businesstoday.com.tw/article/category/183027/post/202104210003/)

### G3：政府專戶沒有結餘與期限規則
- 《公益勸募條例》第 18～20 條（使用計畫核准、結餘款 3 年內執行完畢、成果報告上網）的主詞是「勸募團體」，**不適用政府專戶**。政府專戶只受第 6 條的最低揭露義務約束 — [條例](https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=D0050138)
- 衛福部 2018 年的「地方政府災害捐款管理運用指引」沒有法律授權；立法院預算中心 2022 年指出它拘束力不足 — [預算中心](https://www.ly.gov.tw/Pages/Detail.aspx?nodeid=45805&pid=223464)
- 0206 的 60 案中，8 年後仍有 12 案未結案。

### G4：被漏掉的人，只能靠抗議被看見
- 光復三村因不在「紅色警戒區」被排除在縣府慰問金之外，村民到前進指揮所陳抗 — [中央社](https://www.cna.com.tw/news/aloc/202510060164.aspx)
- 0403 地震：租屋族因戶籍不在受災地址，不符合搬遷救助資格 — [公視 2024-04-08](https://news.pts.org.tw/article/689266)
- 一位獨居的光復一樓重災戶，過去多次因各單位標準不一而沒領到補助 — [三立 2025-12-18](https://www.setn.com/news/1767342)
- **台灣與國際都沒有找到任何系統公開申訴的統計數字**（件數、處理天數、結果）。

### G5：資料無法機器讀取，各帳戶之間也無法串接
- 基金會的收支報表是嵌入網頁的 PNG 圖片，捐款名單是 RAR 壓縮檔；縣府收入是 JPG、支出是 PDF。
- 衛福部公益勸募管理系統**完全不包含政府專戶**；data.gov.tw 也沒有全國性的資料集 — [系統](https://sasw.mohw.gov.tw/app39/fundactivity/fundactivityDetails/16446568)

### G6：制度改革停滯
- 條例從 2020-01-15 後就沒有再修正；第 10 屆的 4 個修正案都已屆期失效；第 11 屆陳菁徽版第 6 條修正案（要求政府勸募前訂辦法、設監督委員會）2024-03 交付審查後就沒有進度 — [提案](https://ppg.ly.gov.tw/ppg/download/agenda1/02/pdf/11/01/03/LCEWA01_110103_00064.pdf)
- 衛福部 2021 年承諾完成研究後「再行研議修正」，至今沒有行政院版草案 — [衛福部說明](https://ppg.ly.gov.tw/ppg/download/agenda1/02/pdf/10/03/12/LCEWA01_100312_00242.pdf)
- 花蓮的自治條例只停在議員倡議與連署，查不到草案。**沒有任何縣市**用自治條例規範災害捐款。
- 2025 年的堰塞湖特別條例要求**特別預算**每月公開進度，但**完全沒有民間捐款的條文**。同一場災害，公帑依法必須每月上網，善款卻不必 — [特別條例](https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=A0030359)

## 4. 根本原因

1. **紀錄由被監督的人保管。** 每一手保管方都自己記帳、自己決定公開什麼、用什麼格式公開。
2. **錢會跨越組織，紀錄卻不會。** 基金會 → 衛福部 → 縣府 → 公所 → 災民，每一手各自為政，沒有共享的狀態。
3. **受益者在治理中缺席。** 災民是被動的「名冊上的一列」，不是有發言權的利害關係人。
4. **改革依賴修法，而修法已經停滯多年。**

## 5. 為什麼現有方案不夠

| 方案 | 做到的 | 沒做到的 |
|---|---|---|
| 法定公開徵信 | 第一手撥款的總額或逐筆紀錄 | 下游送達、機器可讀、跨帳戶串接、災民參與 |
| guangfu.tw | 資訊整合、捐款來源總額、重建動態 | 款項的承諾約束、逐手交付驗證、資格與申訴 |
| RedChain、WFP BB、OpenRelief 等 | ZK 資格、去重、援助點數 | **保管方的用途承諾治理、災民的表決權、被排除者的申訴問責** |
| 修法 | 根本解法 | 停滯多年 |

**我們找到的空白（措辭：「我們沒有找到同時做到以下各項的部署」，不說「全球第一」）：**
1. 由程式碼強制執行的善款承諾：用途上限、結餘規則、改變用途時的公開冷靜期，以及**災民的表決權**
2. 跨保管方的監管鏈：匡列 → 撥付 → 核銷 → 送達，每一手都可以驗證
3. 被排除者的公開問責：申訴件數、處理天數、各簽發者核准與駁回的統計

## 6. 為什麼用 Web3（以及哪裡刻意不用）

**必須用的地方：**
- **被監督的人不能管帳本。** 中央資料庫的管理者可以修改、刪除或選擇性公開。可信的承諾必須獨立於保管方，也不受政黨輪替影響。
- **多個互不隸屬的保管方需要共享狀態**，但沒有一個適合當中心的營運者。基金會、衛福部、縣府、NGO 都不會願意把帳交給對方管。
- **災民需要匿名的一票。** 小社區裡，具名表態可能遭到報復或承受人情壓力。零知識證明可以做到「確認是通過認證的災民、一人一票、但不知道是誰」。
- **法律靠事後查核，程式碼在事前強制執行。** 新加坡在 NKF 之後走立法路線；台灣修法停滯多年，Kept 可以作為自治條例的技術實作。

**刻意不用的地方：**
- 個資、名冊、銀行帳號一律不上鏈。
- 實際付款仍經由銀行；鏈上只記錄承諾、決議、交付的證明，以及雜湊。
- 資格認定仍由公所和村長負責；Kept 讓他們的判斷**可以被追責**，而不是取代他們。

## 7. 解法：Kept 的三個核心機制

> **核心洞見：同一張受災證明，讓你領得到錢，也讓你對錢怎麼用有一票。**

### M1：承諾（Commitment）— 回應 G3、G6
建立基金時就把以下內容寫進合約：
- **用途類別與比例上限**，例如生活慰助 ≤ 60%、房屋修繕 ≤ 30%、社區與心理重建 ≤ 10%
- **結餘規則**：只能用於同一災區的重建，不得轉作其他災害或一般公共工程
- **預定期程**：到期前若要延長，必須公開理由並經災民表決（**不強迫在期限內花完**）
- **改變用途的兩條路：**
  - **緊急調整**：委員會較高門檻＋災民表決通過，立即生效，事後公開說明
  - **結餘或長期用途變更**：公開冷靜期（例如 7 天），期間災民可以表決反對
- 所有基金都由同一個 **Factory 範本**產生，避免保管方另外部署一份合約繞過承諾

### M2：監管鏈（Custody Chain）— 回應 G1、G5
每一筆款項在每一手之間都留下四種狀態：

```
匡列（Allocated）→ 撥付（Disbursed）→ 核銷（Reconciled）→ 送達（Delivered）
```

- **撥付**：每一手轉帳都記錄「從誰到誰、哪個方案、金額、預估戶數」，附銀行交易憑證雜湊
- **核銷**：下游單位提交發放名冊的 **Merkle root**（每戶一筆經雜湊的紀錄），加上總額與戶數
  - **大眾**看得到總額、戶數，以及和預撥數的差額
  - **每一戶受災戶**都可以用自己的憑證驗證「我有被算進去」（Merkle 包含證明），**但沒有人看得到整份名冊**
  - 如果有人被記成已領、實際上沒領到，當事人可以直接提出異議 → 防範幽靈受益人
- **送達**：受災戶本人或代理人（社工、村長，另外標註）簽收
- **漏斗儀表板**：每個方案顯示「匡列 X → 撥付 Y → 核銷 Z → 送達 W」，一眼看出卡在哪一手
- 資料以開放格式輸出（JSON，參考 IATI 和 Open Contracting 標準），可以直接餵給 guangfu.tw 這類平台

### M3：災民之聲（Voice）— 回應 G2、G4
- **匿名表決**：通過認證的災民組成 Semaphore 群組，可以對用途變更、期程延長進行一人一票的匿名表決，也可以匿名推選委員會代表
- **申訴**：任何人（包括從未被登記的人，可以透過村長、社工或自己）都能提出申訴；儀表板公開各村的申訴件數、平均處理天數、結果
- **簽發者問責**：每位簽發者核准、駁回、撤銷的數量都公開，並和官方災情統計比對，異常時亮燈

### 底層：資格憑證（借用成熟方案，不宣稱原創）
- 公所與村長**雙重簽核**後，把受災戶的身分承諾加入 Semaphore 群組，以整場災害＋受災等級為單位
- **每個方案使用不同的 nullifier**（修正 v0.1 的設計）：同一方案不能重複領取，但不同方案之間的紀錄**無法互相連結**，避免小村莊的居民被反推出身分
- 「誰一個方案都還沒領到」由持有名冊的公所在鏈下計算，只把**統計數字**上鏈
- 兩種發放模式：**主動發放**（政府照名冊直接撥款，不需要災民做任何事）；**出示證明**（災民去 NGO 時出示 QR，NGO 不必先拿到名冊就能驗證資格）
- 紙本 QR 卡適合長輩，概念參考日本能登地震時用 Suica 卡登記避難者，以及 Rahat 的 QR 卡
- 引用前例：西班牙紅十字會 RedChain、IEEE S&P 2023 論文 "Not Yet Another Digital ID"（EPFL × ICRC）

## 10. 設計原則

1. **區塊鏈縮到最小、但不可或缺**（見第 6 節）
2. **個資零上鏈**：只放承諾值、雜湊、Merkle root；可對應回個人的鹽值放在鏈下，需要刪除時銷毀即可（因應個資法與 GDPR 的刪除權）
3. **不讓災民多做事**：主動發放優先，紙本卡、代理簽收、不付 gas
4. **不懲罰審慎**：不強迫在期限內花完，要求的是公開與災民同意
5. **讓人的判斷可追責，而不是取代人的判斷**
6. **匿名集合要夠大**：群組以整場災害為單位；儀表板上少於 5 戶的格子不顯示精確數字
7. **尊重原住民族的集體決策與資料主權**：光復受災最重的是阿美族部落（馬太鞍、太巴塱）。表決與申訴要能配合部落會議運作；知情同意必須以族語或部落可理解的方式說明（2026 年曾發生長輩在沒有充分說明下被要求簽土地同意書的爭議 — [上下游新聞](https://www.newsmarket.com.tw/blog/242854/)）
8. **數位公共財（DPG）**：開源授權、開放標準、遵守 do no harm

## 12. 落地路徑與可持續性

- **第一階段（現行法規下即可做）：** 善款仍在銀行；鏈上記錄承諾、決議、撥付憑證雜湊、核銷 Merkle root、送達簽收。保管方自願加入，換取「Kept 認證基金」的信任標章。
- **第二階段：** 以自治條例或修法，要求政府專戶採用可驗證的揭露格式。Kept 可作為 0403 後近 300 人連署所要求的自治條例的技術實作。
- **第三階段：** 《虛擬資產服務法》（2026-06-30 三讀，子法完成後最快 2027 年第一季施行）上路後，合規的台幣穩定幣可以直接進入合約，由程式碼強制執行用途。前例：Binance Charity 的 117,210 USDT 經在地虛擬資產業者換成 357 萬元台幣，捐入賑災基金會。
- **最可能的試點夥伴：** 賑災基金會。它已經每月公開逐筆撥款，也曾撥款 200 萬元給公民科技平台 guangfu.tw，對公民科技有開放態度。
- **與 guangfu.tw 的關係：互補，不是競爭。** guangfu.tw 做資訊整合與社區連結；Kept 提供底層「可驗證的款項與資格」資料，以開放格式供它使用。
- **成本：** L2 上每一筆紀錄的成本很低（待實測後補上每場災害的估算）；開源維護可申請 GSR Foundation、Celo、Stellar 等公共財資助。
- **擴展性：** 可以套用到任何國家的災害善款，例如日本、西班牙、菲律賓。

## 13. 風險、限制與倫理

| 風險或質疑 | 回應 |
|---|---|
| 為什麼不做成政府資料庫就好？ | 被監督的人不能管帳本；而且有多個互不隸屬的保管方（見第 6 節） |
| 保管方在鏈下說謊（垃圾進、垃圾出） | 第一階段無法完全防止，但每一手都留下簽章紀錄，加上災民可以驗證自己的那一筆，說謊的成本會大幅提高；第三階段由程式碼強制執行 |
| 簽發者加入幽靈受益人 | 雙重簽核、簽發者統計和官方數字比對、Merkle 包含證明讓當事人可以異議 |
| 小村莊被反推出身分 | 每方案使用不同 nullifier、匿名集合以整場災害為單位、k-匿名顯示 |
| 簽發的公所知道誰是誰 | 這是事實，本來名冊就在公所。我們保證的是「**公眾與其他單位**無法從鏈上反推出身分」 |
| 合約太死板，跟不上現場需求 | 設有緊急調整路徑（見 M1） |
| 長輩不會用 | 主動發放、紙本卡、代理簽收 |
| 表決被操縱或有人重複投票 | Semaphore 的 nullifier 保證一人一票；認證採雙重簽核 |
| 保管方不願意採用 | 定位成贏回信任的工具（0403 的善款不到 0206 的五分之一）；第二階段走自治條例 |
| 倫理 | 簡報不使用真實受災者姓名；偵查中的案件不下定論；Demo 資料一律標示為模擬 |

## 14. 與現有方案的差異及借用

| | Kept 做什麼 | 借用誰 |
|---|---|---|
| 承諾治理 | **我們沒有找到其他部署** | OpenZeppelin Timelock |
| 監管鏈＋核銷 Merkle | 跨保管方的四段式狀態 | Merkle 證明、IATI、Open Contracting |
| 災民匿名表決 | **把資格群組延伸為治理權** | Semaphore、MACI（Dora Factory） |
| 申訴與簽發者問責 | **我們沒有找到公開申訴統計的系統** | 菲律賓 DROMIC 的公開報表格式 |
| ZK 資格與去重 | 不宣稱原創 | RedChain、NYADID（IEEE S&P 2023）、WFP BB |
| 紙本憑證 | 不宣稱原創 | Rahat QR 卡、Inji 離線 QR、能登地震 Suica |

**與西班牙 UMA 冠軍隊（Proof of Aid）的差異：** 他們證明「援助送到了」；Kept 讓**保管方的承諾**與**被排除的人**都可以被驗證，並讓災民有一票。

## 15. Demo 劇本（模擬光復堰塞湖，全程英文介面）

1. **用範本建立基金**：宣告用途上限與結餘規則 → *對應 G3*
2. **捐款湧入**，儀表板即時更新
3. **公所與村長雙重簽核**受災戶；**南富村一戶不在名單上** → 提出申訴 → 儀表板亮紅燈 → 受理並加入 → *對應 G4*
4. **監管鏈**：基金會預撥給衛福部 → 衛福部上傳核銷 Merkle root → 漏斗顯示「撥付 100% → 核銷 60% → 送達 40%」 → *對應 G1*
5. **受災戶驗證「我有被算進去」**；另一戶發現自己被記成已領、實際沒拿到 → 提出異議 → *對應幽靈受益人*
6. **到 NGO 出示 QR**，當場驗證後領取；同一方案再領一次被擋下
7. **保管方提議把結餘轉作「縣府公共工程」** → 合約直接拒絕（違反結餘規則）；改提「延長期程 6 個月」 → 進入冷靜期 → **災民匿名表決** → 結果寫回合約 → *對應 G2*
8. **開放資料匯出**，展示如何供 guangfu.tw 這類平台使用
